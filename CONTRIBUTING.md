# Contributing

Thanks for your interest in OSPARK Starter. Please keep changes reproducible and local-first.

1. Open an issue describing the behavior or adapter you want to add.
2. Keep simulated records unmistakably labeled and never mix them with live acceptance evidence.
3. Add tests for status failures, empty states, and unconfigured services.
4. Do not add automated tool execution, privileged OS operations, private runtime paths or third-party assets without a separate security/license review.
5. Run `npm test` and `npm run check` before requesting review.

This public reference should remain usable without requiring an inference engine, cloud account or GPU.
